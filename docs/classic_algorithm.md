# Classic 算法考古记录

> 本文档是 `legacy/xiangsudian.py` 的**考古结论落盘**，用于指导后续 Classic 算法复刻。
> 只陈述已从原始代码确认的行为，不包含推测、不包含"改进"、不包含 Modern 算法设计。
> 本文件与 `legacy/*.py` 相互独立：legacy 原件永不修改，复刻以新代码实现。

## 总览

`xiangsudian.py` 是一条**自定义的规则空间密度二值化**管线：先把图缩放到目标网格分辨率，再在网格上用**两轮独立的灰度阈值**决定每个逻辑像素是黑还是白，最后用最近邻放大还原为纯黑/纯白的方块。

这里特别强调：这是一种**自定义行为**，不要把它改称标准 Bayer 有序抖动、Floyd–Steinberg 误差扩散，或其它任何既有命名算法。它的网点密度由"偶数行 × 偶数列的稀疏子网格 + 两级阈值"决定，而非任何经典抖动的误差传播或矩阵映射。

## 参数与默认值

| 参数 | 含义 | 默认值 |
|---|---|---|
| `-d` | 输出图像宽度（水平像素） | 1000 |
| `-s` | 网点尺寸（降采样系数，等价于每个逻辑像素的边长） | 2 |
| `-t` | 灰度阈值（第一轮） | 127 |
| `-b` | 黑色阈值（第二轮） | 60 |
| `-c` | 是否直方图均衡，`y`/`n` | `y` |
| `-i` / `-o` | 输入 / 输出文件 | 必填 |

## 处理流程

### 1. 输入与可选预处理

- 以 `cv2.imread(input_file, cv2.IMREAD_UNCHANGED)` 读取。
- 默认 `c='y'` 时：
  1. 以 `cv2.imread(input_file, 0)` 灰度重读原图（**绕开上一步的彩色读取结果**）；
  2. 对灰度图做 `cv2.equalizeHist()`；
  3. 用 `cv2.cvtColor(..., cv2.COLOR_GRAY2BGR)` 把均衡后的单通道转回三通道 BGR。
- 因此**默认情况下原始颜色信息被丢弃**：直方图均衡只作用在灰度上，色彩被整体替换为均衡后的灰度值（三个通道相等）。
- `-c` 是黑名单判断：只有等于 `'y'` 才触发预处理，其余任何值（含 `'Y'`）都静默跳过。

### 2. 两阶段缩放

- 第一次：`cv2.resize(img_input, (d, d * H / W))`，把宽缩到 `d`，高按原比例。
- 第二次：`cv2.resize(img, (W/s, H/s))`，再缩到上一步尺寸的 `1/s`。
- **两次调用都没有显式指定 interpolation**，因此按 OpenCV 默认行为使用 `INTER_LINEAR`。
- 这意味着**二值化之前存在正常的灰度中间值和双线性平滑插值**。降采样图 `img_d` 不是二值的，而是连续灰阶。

### 3. 二值画布

- 创建与降采样图 `img_d` 同尺寸的三通道画布 `img_r_d`，初始**全白** `[255,255,255]`。
- 后续所有写操作只写 `0`（黑）或保留 `255`（白），**最终逻辑画布严格二值**。

### 4. 第一轮阈值

- 仅遍历 `(偶数行, 偶数列)` 位置：`for i in range(0, H, 2)` × `for j in range(0, W, 2)`。
- 取该位置降采样图三通道均值 `a = (int(B)+int(G)+int(R))/3`。
- 若 `a < t`，把输出画布该位置三通道全部置 `0`（黑）。

### 5. 第二轮阈值

- 遍历**全部**位置：`for i in range(0, H)` × `for j in range(0, W)`。
- 取三通道均值 `a`，若 `a < b`，把输出画布该位置三通道全部置 `0`（黑）。
- 循环体内**只有 `if a < b:` 一个分支，没有 `else`**，因此**不存在把第一轮已变黑的像素重新设白的行为**。第二轮只能把白变黑，不能把黑变白。

### 6. 精确真值

设 `a(x,y)` 为降采样图上位置 `(x,y)` 的三通道均值，初始画布全白，则最终取值：

```
黑 = { a < b }  ∪  { y 为偶数 ∧ x 为偶数 ∧ b ≤ a < t }
```

（第二项写成 `b ≤ a < t` 是为了与第一项无重叠分解；`a < b` 的部分已由第一项覆盖。）

默认 `b=60, t=127` 时：

| 均值区间 | 输出 |
|---|---|
| `a < 60` | 所有位置为黑 |
| `60 ≤ a < 127` | 仅「偶数行 × 偶数列」位置为黑，即固定 2×2 单元中的 **1/4 黑点密度** |
| `a ≥ 127` | 白 |

其中第二行是这个算法最关键的视觉特征：在中间灰区，网点只在 `(偶,偶)` 位置出现，其余 3/4 保持白色，形成规则的 1/4 密度网点图案；而极暗区（`a < 60`）则四邻全黑。

### 7. 最终放大

- `cv2.resize(img_r_d, (d, d * H/W), interpolation=cv2.INTER_NEAREST)`。
- 用**最近邻**把低分辨率画布放大回目标尺寸，因此**每个逻辑像素对应一个规则的纯黑或纯白方块**，不产生新的灰阶或过渡。

### 8. `-b` 的 CLI bug

- `usage()` 文本中确实列出了 `-b`（`-b:therod for black,0-255,defualt 60`）。
- `getopt.getopt(..., '-h-d:-s:-i:-o:-c:-t:-b:')` 的参数字符串里也声明了 `-b:`。
- 但后续 `if/elif` 解析代码里，`-t` 分支被误写了两次：

  ```python
  elif cmd == '-t':
      t = int(arg)
  elif cmd == '-t':      # 应为 '-b'
      t = int(arg)
  ```

  由于 `if/elif` 链第一个 `-t` 分支已匹配，第二个 `-b`（实为重复 `-t`）分支**永远不可达**。
- 因此命令行传入 `-b` 后，会静默落入"无任何 `elif` 匹配"的结局，**不会更新变量 `b`**。
- **默认 `b=60` 本身在第 28 行正常初始化，并正常参与第二轮阈值判断**——变量有效，只是 CLI 无法覆盖它。
- 结论：除非当年直接修改源码，否则实际运行时 `b` 基本固定为 60。

## 关键区分（易错点）

必须区分两个不同的命题：

| 命题 | 真值 |
|---|---|
| 最终输出严格二值 | ✅ **真**：画布只写 0 或 255，最近邻放大后仍是纯黑/纯白方块 |
| 处理中间过程完全没有灰度 / 平滑插值 | ❌ **假**：两阶段缩放默认用 `INTER_LINEAR`，二值化前存在连续灰度中间值和双线性插值 |

不要因为"最终是二值图"就误以为"整个过程都是二值的"——这两件事在 Classic 里是分离的：**灰度与平滑发生在缩放阶段，二值化发生在阈值阶段，二者先后明确。**
